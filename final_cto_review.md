## 🧘 1. РЕВЬЮ СОДЕРЖАНИЯ И ПРОДУКТОВОЙ ФИЛОСОФИИ (Content & Vision)

Проект Inside English v2.0 совершил колоссальный качественный скачок: от простого образовательного приложения до **премиальной психологически комфортной экосистемы**, объединяющей изучение языка, эмоциональную сонастройку и преодоление барьеров общения в реальном времени.

### Сильные стороны продуктовой логики:
*   **Карта эмоциональных состояний (State Selector):** Выбор уроков под текущее настроение (🧘 `calm` / ⚡ `focus` / ⚡ `energy` / 🌙 `sleep`) убирает «геймификационный стресс», превращая учебу в медитативный ритуал.
*   **Концепция «Inside Bridge» (Flow Talk):** Это мощнейший виральный драйвер. Использование спикерфона как MVP снимает необходимость сложной интеграции с телефонией и решает проблему нативной записи вызовов на iOS.
*   **Качественный контент-набор:** Оригинальные, профессионально озвученные уроки-аффирмации (Morning Calm, Deep Focus, Energy Boost, Sleep Stories) с пословными таймкодами дают мгновенный «wow-эффект» при первом запуске плеера.

## 💻 2. АУДИТ КЛИЕНТСКОЙ АРХИТЕКТУРЫ (Frontend & UX)

Фронтенд-архитектура, собранная на базе **Next.js 14 (App Router)**, представляет собой образец современного отзывчивого Single Page Application (SPA).

### Архитектурный разбор ключевых модулей:
1.  **Двухрежимный плеер (`components/PersistentPlayer.tsx`):**  
    *   *Реализация:* Идеальное разделение на парящий Mini-bar (позволяющий бродить по приложению в процессе воспроизведения) и полноэкранный Full-screen плеер.
    *   *Связь со стейтом:* Плеер напрямую подписан на Zustand-стор (`usePlayerStore.ts`). Переключение языков на лету (*RU / RU-EN / EN*) происходит со скоростью `0 мс` без перезагрузки аудио-элемента.
    *   *Фикс субтитров:* Исключена коллизия рендеринга. Плеер считывает tokens индивидуально загруженного трека из Zustand, а не из общего глобального массива.
2.  **ИИ-Коуч и Интерактивный дашборд (`app/page.tsx`):**  
    *   *Интеграция:* Виджет чекина органично вписан в дашборд. Нажатие отправляет POST-запрос, выводит напутствие ИИ на русском языке, динамически формирует кастомный Track и запускает его воспроизведение с пословной Lyrics-подсветкой.
3.  **Пространство Inside Bridge (`components/BridgeWorkspace.tsx`):**  
    *   *UX подсказок:* Реализован концепт **«Тихих подсказок» (Quiet Hints)**. Карточки ответов занимают одну строку, легко считываются боковым зрением при звонке и посылают нативную тактильную вибрацию (`TelegramSDK.triggerHaptic('success')`) при обновлении, исключая необходимость постоянно смотреть на экран.
    *   *Принцип приватности:* Внедрен тумблер **Incognito**. При его включении реплики обрабатываются только в RAM и не пишутся в историю БД.
4.  **Анимации и Доступность (`lib/animations.ts`):**  
    *   *Физика:* Внедрены честные пружинные пресеты (`springConfigs.gentle`, `bouncy`, `snappy`). Варианты ответов в Quiz появляются с staggering-эффектом (каскадная задержка 60 мс). При неправильном ответе карточка делает физическое затухающее покачивание по оси X (Shake).
    *   *Доступность (a11y):* Через хук `useReducedMotion()` реализована обязательная защита для людей с вестибулярной чувствительностью — при включении системной настройки «Уменьшение движения» все пружины и 3D-перевороты плавно отключаются.

## 🔒 3. АУДИТ СЕРВЕРНОЙ АРХИТЕКТУРЫ И СУБД (Backend & Security)

Бэкенд-слой, развернутый на **Next.js 14 API Route Handlers** и **Supabase PostgreSQL**, спроектирован с учетом требований OWASP и максимальной защиты облачного баланса от накруток.

### Оценка безопасности и контуров защиты:
1.  **Защита платных текстов от утечек (Vulnerability #2 - FIXED):**  
    Поле `tokens` (содержащее полный сценарий уроков) удалено из общей таблицы `tracks`. Оно вынесено в таблицу `track_contents`, защищенную RLS-политикой. База данных физически блокирует чтение tokens бесплатных пользователей на премиальных треках.
2.  **Защита авторизации и Replay-атак (Vulnerability #3 - FIXED):**  
    Роут `/api/auth/telegram` проверяет подпись `initData` с помощью `crypto.timingSafeEqual` (противодействие Timing-атакам) и отсекает запросы, подписанные серверами Telegram более 24 часов назад, полностью исключая атаки повторения.
3.  **Защита баланса ИИ-запросов (Vulnerability #6 - FIXED):**  
    Все тяжелые ИИ-эндпоинты (`/api/ai/coach/check-in`, `/api/bridge/voice/process`, `/api/bridge/message/send`) защищены двойным барьером:
    *   *Rate Limiting:* Лимитер Sliding Window отсекает спам-ботов по IP (5/мин) и по User ID (10/мин).
    *   *Premium Gate:* В продакшне роуты жестко проверяют настройки профиля пользователя. Если `is_premium !== true` — запрос прерывается до вызова API OpenAI, возвращая `402 Payment Required`.
4.  **Сквозной биллинг и Вебхук-защита (Vulnerability #3b & #7 - FIXED):**  
    *   *Сценарий Telegram Stars:* Роут `/api/telegram/webhook` полностью закрывает цикл платежей Stars. Он проверяет входящую подпись через тайминг-безопасную сверку секретного токена `X-Telegram-Bot-Api-Secret-Token` (исключает бэкдор бесплатного премиума).
    *   *Авто-апрув транзакций:* Обработчик за долю секунды отвечает Telegram на пре-чекаут запросы (`pre_checkout_query`), предотвращая автоматическую отмену платежей.
    *   *Successful Payment:* Извлекает UUID покупателя из инвойса, находит пользователя в БД по Telegram ID мосту (`tg_{id}@inside-english.telegram`) с помощью сервис-клиента и активирует Premium.
    *   *TRANSFER:* Корректно переводит entitlement, деактивируя старого владельца и включая доступ новому.

## ⚙️ 4. АУДИТ СИСТЕМЫ СБОРКИ И ДЕПЛОЯ (DevOps)

Система сборки Next.js решена на высочайшем уровне гибкости:
*   **Гладкий SSR-билд:** Обычный `npm run build` успешно собирает серверный дистрибутив со всеми 22 динамическими роутами, middleware-рефрешем кук сессии и rate-лимитами.
*   **Гладкий Static-билд:** Команда `npm run export` временно изолирует `/api`, переключает конфиг в `output: 'export'` и компилирует чистый SPA-дистрибутив для iOS-приложения (Capacitor) или GitHub Pages.
*   **Regression Guard в CI/CD:** Перед каждым деплоем в облако GitHub Pages воркфлоу запускает верификацию серверного билда Next.js, гарантируя, что разработчики никогда случайно не сломают боевой Vercel-деплой.

## 🏁 5. ФИНАЛЬНЫЙ СУПЕР-ЧЕКЛИСТ ПЕРЕД ЗАПУСКОМ (Definition of Done)

Выполните эти шаги последовательно, чтобы приложение заработало в полную силу на реальных серверах:

- [ ] **1. Заливка миграций БД:** Скопируйте содержимое файлов `schema.sql`, `storage_policies.sql`, `push_tokens_migration.sql` и нашего нового файла **`supabase_migrations.sql`** (содержит таблицы для Коучинга и Bridge) и примените их в Supabase SQL Editor.
- [ ] **2. Настройка переменных окружения (.env):** Убедитесь, что на хостинге Vercel прописаны ключи `TELEGRAM_BOT_TOKEN`, `OPENAI_API_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `REVENUECAT_WEBHOOK_SECRET` и наш новый секрет **`TELEGRAM_WEBHOOK_SECRET_TOKEN`**.
- [ ] **3. Привязка вебхука бота:** Вызовите в браузере настроечный URL для привязки защищенного секретного токена к вашему серверу:
   `https://api.telegram.org/bot<TOKEN>/setWebhook?url=https://<YOUR_DOMAIN>/api/telegram/webhook&secret_token=<YOUR_TELEGRAM_WEBHOOK_SECRET_TOKEN>`
- [ ] **4. Проверка статуса вебхука:** Вызовите `https://api.telegram.org/bot<TOKEN>/getWebhookInfo` и убедитесь, что `url` прописан верно, а ошибки отсутствуют.
- [ ] **5. Интеграция с RevenueCat:** Пропишите ваш `NEXT_PUBLIC_REVENUE_CAT_API_KEY_IOS` в переменные окружения, сопоставьте тарифы `monthly_premium` / `annual_premium` в кабинете RevenueCat и протестируйте пару платежей в TestFlight Sandbox на iPhone.
